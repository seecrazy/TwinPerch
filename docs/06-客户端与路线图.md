# 客户端架构与开发路线

## 1. 工程结构

```
TwinPerch/
  App/                SwiftUI：配对 / 会话 / 聊天 / 设置 / 门禁
  TwinPerchKit/       无 UI 依赖的领域层
    Crypto/           TP-Crypt v1 实现（纯 CryptoKit）
    Session/          会话状态机：链状态、跳过密钥、去重、ACK 捎带
    Vault/            GRDB SQLite + 列级 AES-GCM（vault_key）
    Transport/        RelayTransport 抽象 + Email / Cloudflare 实现
    Push/             推送代理客户端
  Worker/             twinperch-relay（TypeScript）
  PushProxy/          通知代理（TypeScript）
  SpecTests/          协议测试向量 + Python 交叉验证脚本
```

## 2. 本地存储要点（隐私宣称的实现保障）

- 消息正文、会话状态列级加密（AES-GCM，per-record key 由 vault_key + 表 id + 行计数派生，nonce 确定性无碰撞）
- 附件：每文件独立 file_key（存 DB）；文件本体 `.completeFileProtection` 锁屏不可读
- **Application Support 整目录 `excludedFromBackup`**——否则聊天库默认进 iCloud 备份，"不存云端"宣称穿帮。加进 CI 检查项
- 门禁：`.deviceOwnerAuthentication`（Face ID / Touch ID / 密码三选一），冷启动 + 后台超 5 分钟触发
- Keychain 用 `WhenUnlockedThisDeviceOnly`，不绑生物 ACL（保证推送唤醒的后台收发不弹窗）；通知预览默认隐藏、解锁后显示

## 3. 路线图（修订版）

### Phase 0 — 验证（1-2 周，每项都可证伪）
| # | 任务 | 出口标准 |
|---|---|---|
| 1 | TP-Crypt 参考实现 + Python 交叉验证 | 握手/棘轮/乱序/重同步/重键各 ≥10 组测试向量对拍通过 |
| 2 | QQ 邮箱 IMAP IDLE 在 iOS 真机的存活与延迟实测 | 前台秒级收信；后台行为记录在案 |

| 5 | 加密协议外审 | 至少一位密码工程背景者评审 01 文档 |

### Phase 1 — MVP（邮箱主干）
- ✅ 配对/握手（QR + 安全码）+ CryptoCore + Vault（48/48 测试，双实现交叉验证）
- ✅ EmailTransport 文本收发（IMAP/SMTP 子集 + MIME + IDLE 轮询编排，协议逻辑已测）
- ✅ 重配对与安全码变更提示（KEY_NOTICE 帧 + 系统消息 UI）
- ⏳ 门禁（iOS 壳层 LA）与真机验证（人工项）
- 交付标准：两台真机经 QQ 邮箱完成配对与往返消息；飞行模式恢复后自动补收，无重复、无乱序错乱

### Phase 2 — 体验
- ✅ 推送代理：Worker（PushProxy/）+ App 客户端（Push/PushClient）已完成，实连验证人工项
- ✅ CloudflareTransport（WS 帧协议+鉴权）+ App 内部署流（CloudflareDeployer + /bootstrap）
- ⏳ 图片/文件传输（加密 + chunk）——协议 type=1 清单帧已预留
- ✅ 已读回执（加密捎带 + 控制帧）UI
- ✅ 设计系统层（DS：暮沙/黛蓝双人色板、衬线品牌时刻、安全码色块可视化、跨平台组件）
- ✅ 设置页（连接方式/授权码分服务商引导/推送 opt-in/重新配对/隐私说明）
- ✅ 发件队列（先入箱后发送，失败可重发，上线自动补发——发送永不静默丢失）
- ✅ 附件分块协议（type=1 manifest 帧，512KB 分块，接收方重组入库）
- ✅ 门禁状态机进 AppCore（LA 可注入评估器，冷启动+后台超阈值锁定）
- ✅ 解密失败用户可见提示 + 一键重同步；历史分页加载
- ⏳ 消息搜索、局域网直连大文件
- 决策：输入状态（"正在输入"）v1 不做——暴露打字时机元数据，与隐私宣称冲突，写入产品页当卖点

### Phase 3 — 扩展
- 便携 relay 二进制（同一协议第三实现：Docker/静态二进制，情侣 VPS/NAS 自托管）
- 加密导出备份（用户主动、口令派生密钥）
- 多设备（协议 v2：每设备独立链，放宽单设备假设）
- Android（届时评估 Rust core + uniffi，协议字段已版本化）
