# 传输层抽象（RelayProtocol）

> 设计原则：加密层不感知传输，传输层不感知内容（只见 Envelope 字节）。任何传输实现只需满足本契约即可接入。

## 1. 接口定义（Swift 伪码）

```swift
enum TransportKind { case email, cloudflare, portableRelay }

enum TransportEvent {
    case envelope(TransportEnvelope)                       // 收到密文
    case connectionState(ConnectionState)                  // .online / .offline / .degraded
}

enum ProvisioningCredential {
    case email(EmailAccount)                               // 服务商预设 + 用户名 + 授权码
    case cloudflareRelay(oauthToken: String)               // 用后即焚，不持久化
    case manualRelay(url: URL, roomKey: Data)              // 自托管 relay 手动接入
}

protocol RelayTransport {
    var kind: TransportKind { get }
    /// 一次性配置：邮箱登录 / CF 部署 / 手动 relay。成功后 credential 不得留存明文。
    func provision(_ credential: ProvisioningCredential) async throws
    /// 启动收信循环（推送型 = WS 长连；拉取型 = IDLE/轮询）
    func start(session: TransportSession) -> AsyncStream<TransportEvent>
    func send(_ envelope: Data) async throws
    /// 拉取积压（推送型实现可为空操作，由 WS 推送覆盖）
    func fetchPending() async throws -> [TransportEnvelope]
    /// best-effort 传输层回执，用于服务端信箱清理（密码层 ACK 与其独立）
    func ack(ids: [String]) async
    func stop() async
}

struct TransportSession { let roomID: Data; let authKey: Data }   // = room_id / k_room
```

## 2. 投递语义（统一契约）

- **有序**：同一发送方方向按 chain_index 严格有序
- **at-least-once**：接收方按 `(session_id, sender, chain_index)` 去重（加密协议 §6）
- **回执**：应用级 ACK 是加密的控制帧，与传输无关；传输层 `ack` 仅用于服务端信箱清理，可选实现
- **离线信箱**：
  - 推送型（CF / 自托管）：服务端暂存，TTL 14 天，ACK 后删除
  - 拉取型（邮箱）：密文邮件留存在用户自己的邮箱，ACK 后 IMAP 删除（设置可改"保留副本"）
- **载荷上限**：email 单封约 20MB（超过拆 chunk）；CF 1MB；更大文件走局域网直连（第二阶段）

## 3. 元数据披露矩阵（诚实清单，进产品页）

| 传输 | 谁能看到什么 |
|---|---|
| 邮箱 | 服务商：双方邮箱地址、时间、频率、邮件大小；**内容/密钥不可见** |
| Cloudflare | Cloudflare 公司：IP、时间、room_id、流量形态；内容/密钥不可见（k_room 残留风险见加密协议 §8） |
| 自托管 | VPS 主机商：IP、时间；其余只有这对情侣自己 |

## 4. 断线与重连

所有实现统一：指数退避（1s 起，上限 64s，带抖动）；持续失败进入 `.degraded` 并上报 UI；网络切换（Wi-Fi ↔ 蜂窝）立即重连。后台存活策略按传输各自处理（邮箱见 03 §4，CF 见 04 §6）。

## 5. 多传输共存（第二阶段）

两个传输可挂同一 session_id（密文完全相同）：WS 在线优先走 CF，断线由邮箱兜底。MVP 阶段只启用一条。
