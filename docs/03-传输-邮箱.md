# 邮箱传输实现（EmailTransport）—— 主干

> 选型依据：用户已有邮箱即信箱，零注册、零部署（v1 方案的"部署中转站"整步消失）；QQ/163 等国内服务商完全可达；Delta Chat 模式已被全球数百万用户验证。

## 1. 账号配置流程（App 内，本方案唯一门槛，重点打磨）

1. 选择服务商：预设表覆盖 QQ / 163 / 126 / Gmail / Outlook / iCloud / 自定义
2. 输入邮箱 + 凭证。**国内服务商要求"授权码"而非登录密码**——按服务商提供截图级引导（QQ 邮箱：设置 → 账户 → 开启 IMAP/SMTP → 生成授权码）
3. App 验证 IMAP + SMTP 登录 → 创建专用文件夹 `TwinPerch`
4. 对方邮箱地址在配对时经 QR 交换（加入 QR 字段），无网络交换

安全约束：凭证存 Keychain（`WhenUnlockedThisDeviceOnly`）；引导用户生成**专用授权码**（可单独撤销，泄露不波及邮箱主密码）。

## 2. 邮件格式

```
From:        发送方邮箱
To:          对方邮箱
Subject:     "TwinPerch"（定长，无任何内容信息）
Message-ID:  <{session_id_hex}.{chain_index}@twinperch>
Body:        空
附件:        twinperch.dat（Envelope 二进制，加密协议 §5）
```

收发仅使用 `TwinPerch` 文件夹，用户其他邮件零接触。

## 3. 发信

SMTP，一条消息一封邮件（不合并批量化，保实时性）；发送失败入本地队列，退避策略同传输抽象 §4。

## 4. 收信

| 场景 | 机制 |
|---|---|
| 前台 | IMAP IDLE 长连接，秒级到达 |
| 后台 | BGTaskScheduler（BGAppRefreshTask，机会性）+ 推送代理唤醒（opt-in） |
| 冷启动 | 全量拉取 UNSEEN |

流程：`UID SEARCH UNSEEN` → 逐封取附件 → 密码层解密入 Vault → 标记 `\Deleted` → `UID EXPUNGE`（ACK 后删除，兑现"信箱清空"；设置可改为移入 Archive）。

## 5. IMAP/SMTP 子集

不需要完整邮件客户端，仅实现：
- IMAP：AUTHENTICATE PLAIN、SELECT、IDLE、SEARCH、FETCH、STORE、EXPUNGE、CREATE
- SMTP：AUTH PLAIN/LOGIN、MAIL FROM/RCPT TO/DATA

实现路径：先评估现成库（swift-imap / MailCore2）；不足则手写子集（预估 ~1.5k 行，协议简单可控）。

## 6. 限制与已知问题

| 问题 | 对策 |
|---|---|
| 服务商发信频控（QQ 个人邮箱约数百封/天） | 正常情侣用量（<200/天）远低于限；触限时 UI 明示并转积压队列 |
| iOS 后台挂起 IDLE | 实时性依赖推送代理（Delta Chat 同款问题、同款解法），产品页诚实标注"通知可能延迟" |
| 附件大小 | 单封 ~20MB；超过拆 chunk（envelope type=1 清单声明分块元数据，第二阶段） |
| 邮箱服务商风控变化 | 多服务商预设 + 队列降级 + CF 传输兜底（海外） |

## 7. 大陆可用性

QQ/163/126 的 IMAP/SMTP 在大陆直连稳定，这是邮箱被定为主干的根本原因。Gmail 大陆不可达——服务商预设表按区域排序（大陆设备默认展示国内服务商在前）。
